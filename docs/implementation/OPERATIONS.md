# Operations

Every command below runs **inside the Linux reference environment** (WSL2 Ubuntu 24.04),
not on Windows. Open it with:

```bash
wsl -d Ubuntu-24.04
cd "/mnt/d/GitHub/MP2 - Media Personality Projections"
```

`infra/scripts/mp2.sh` is the single operations entrypoint. Run it with no arguments for
the command list. Everything it does can also be done with plain `docker compose` from
`infra/compose/`; the script exists so the documented path and the real path cannot drift.

## Compose profiles

Profiles exist so a constrained machine never has to run everything at once. **No profile
starts automatically.**

| Profile | Services | When |
|---|---|---|
| `core` | postgres, temporal, seaweedfs, api, worker-cpu, model-gateway | The working stack |
| `ui` | web | Browsing the console |
| `admin` | temporal-ui | Inspecting workflows in a browser |
| `llm` | llama-server | Local generative model (CPU-capable; needs a GGUF at `models/model.gguf`) |
| `gpu` | worker-gpu, llama-server | **Not usable on DEV-01** (no NVIDIA GPU) |
| `ops` | otel-collector, prometheus, grafana | Metrics and dashboards |

## Start and stop

```bash
infra/scripts/mp2.sh up            # core profile, waits for health, prints status
infra/scripts/mp2.sh status
infra/scripts/mp2.sh stop          # stop containers, keep them and their data
infra/scripts/mp2.sh down          # remove containers and networks; named volumes survive
```

Optional profiles:

```bash
infra/scripts/mp2.sh up-ui         # console on http://127.0.0.1:5173
infra/scripts/mp2.sh up-admin      # Temporal UI on http://127.0.0.1:8233
infra/scripts/mp2.sh up-ops        # Prometheus 9090, Grafana 3000, OTLP 4317/4318
infra/scripts/mp2.sh up-llm        # llama.cpp server (CPU); needs models/model.gguf
```

> The `ops` profile starts a collector, Prometheus and Grafana, but **no MP2 service emits
> telemetry yet** — there is no OpenTelemetry SDK in the images. The profile is a
> placeholder; see IMPLEMENTATION_STATUS.md.

> The `llm` profile needs a GGUF model at `models/model.gguf`. **None is installed**, and
> the generative path has never been exercised on this machine. With no model configured
> (`MP2_LLAMA_MODEL_ID` unset), the Model Gateway routes local semantic work to the
> deterministic baseline adapter instead — see `docs/adr/0002-*`.

Logs:

```bash
infra/scripts/mp2.sh logs worker-cpu 100
```

> **After a WSL restart, recreate the core containers.** Containers restarted by Docker can
> come back holding stale container IPs for services whose network was recreated, which
> shows up as `connection refused` against an address no service occupies any more. Run
> `infra/scripts/mp2.sh down && infra/scripts/mp2.sh up`. See TROUBLESHOOTING.md.

## Database

```bash
infra/scripts/mp2.sh migrate              # alembic upgrade head
infra/scripts/mp2.sh migration-status     # alembic current
infra/scripts/mp2.sh psql -c '\dt'        # psql against the mp2 database
infra/scripts/mp2.sh revision "add x"     # autogenerate a migration
```

### Back up and restore PostgreSQL

```bash
infra/scripts/mp2.sh backup                                   # -> data/backup/mp2-<utc>.dump
infra/scripts/mp2.sh restore data/backup/mp2-20260920T221500Z.dump
```

`backup` writes a custom-format dump. `restore` runs `pg_restore --clean --if-exists`,
which **drops and replaces** existing objects — take a fresh backup before restoring over a
database you care about. Object storage is not covered by this dump; `mp2-raw` is the
system of record for bytes and must be backed up separately before it holds anything that
is not reproducible.

## Object storage

```bash
infra/scripts/mp2.sh objects          # every bucket and its contents
infra/scripts/mp2.sh clean-derived    # delete mp2-normalized + mp2-derived only
```

`clean-derived` is the disposable-artifact reclaim path. It never touches `mp2-raw` or
PostgreSQL, and everything it deletes is regenerated by rerunning the analysis.

Buckets: `mp2-raw` (source bytes, authoritative), `mp2-normalized` (deterministic
intermediates), `mp2-derived` (scene packets and derived artifacts), `mp2-model-cache`,
`mp2-eval`, `mp2-backup-staging`.

## Test media and analysis

```bash
infra/scripts/mp2.sh fixture           # synthetic AV fixture (silent tone + test pattern)
infra/scripts/mp2.sh speech-fixture    # synthetic fixture containing speech, for ASR
```

Register a work, attach the asset and launch the workflow. Rights, provenance and retention
are **required** — the API rejects the request without them:

```bash
MEDIA=$(curl -s -X POST http://127.0.0.1:8000/v1/media \
  -H 'content-type: application/json' \
  -d '{"title":"Synthetic AV Fixture","work_type":"short","edition_label":"dev"}')
MID=$(echo "$MEDIA" | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')

ASSET=$(curl -s -X POST "http://127.0.0.1:8000/v1/media/$MID/assets" \
  -H 'content-type: application/json' \
  -d '{"local_path":"/media/synthetic-av.mp4",
       "provenance_class":"synthetic",
       "rights_access_class":"redistributable",
       "retention_class":"project"}')
AID=$(echo "$ASSET" | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')

curl -s -X POST "http://127.0.0.1:8000/v1/media/$MID/analyze" \
  -H 'content-type: application/json' \
  -d "{\"source_asset_id\":\"$AID\",\"parameters\":{}}"
```

`local_path` must be inside the container's ingest root (`/media`, bound read-only from
`data/ingest/`). Paths outside it are refused with HTTP 403.

Inspect the result:

```bash
curl -s http://127.0.0.1:8000/v1/analysis-runs/<run-id> | python3 -m json.tool
curl -s http://127.0.0.1:8000/v1/analysis-runs/<run-id>/evidence | python3 -m json.tool
```

## Workflows

```bash
infra/scripts/mp2.sh workflows                  # list workflow executions
infra/scripts/mp2.sh workflow <workflow-id>     # full event history
infra/scripts/mp2.sh queues mp2-cpu             # pollers and backlog for a task queue
```

Task queues: `mp2-io`, `mp2-cpu`, `mp2-gpu`, `mp2-semantic`, `mp2-review`. The workflow is
hosted on `mp2-io`; in the single-worker development profile one process polls all queues.

For a browser view: `infra/scripts/mp2.sh up-admin`, then http://127.0.0.1:8233
(bound to loopback only).

## Tests and linting

```bash
infra/scripts/mp2.sh test                       # full suite inside the runtime image
infra/scripts/mp2.sh test tests/unit -q         # a subset
infra/scripts/mp2.sh lint                       # ruff
infra/scripts/mp2.sh typecheck                  # mypy --strict
infra/scripts/mp2.sh check                      # lint + typecheck + test
```

Integration tests need a running stack and skip cleanly without one:

```bash
infra/scripts/mp2.sh up && infra/scripts/mp2.sh fixture
infra/scripts/mp2.sh test tests/integration
```

The suite runs in a `test` image built on the exact runtime layers, so it exercises what
ships rather than a separate developer environment. Expect roughly three minutes on DEV-01;
numba JIT warm-up and optical flow dominate.

## Local-only mode

Local-only is the default: `MP2_EXTERNAL_MODELS_ENABLED=false`, no API key is configured,
and no test requires one.

```bash
infra/scripts/mp2.sh local-only     # gateway policy, routing, and a worker egress probe
```

This prints the gateway's effective policy, which local adapter it would route to, and
whether the worker can reach a public model provider.

## Security checks

```bash
infra/scripts/mp2.sh ports          # published listeners; anything non-loopback is a finding
infra/scripts/mp2.sh local-only     # gateway policy, routing, and a worker egress probe
```

Only three MP2 services are reachable from the host, and only when their profile runs:

| Reachable | Not reachable from the host at all |
|---|---|
| api `127.0.0.1:8000` | postgres, temporal, seaweedfs, model-gateway, worker-cpu |
| web `127.0.0.1:5173` (ui) | |
| temporal-ui `127.0.0.1:8233` (admin) | |
| prometheus / grafana / otel (ops) | |

PostgreSQL, Temporal and SeaweedFS are attached only to internal networks, so they have no
route to the host bridge and publish nothing — this is structural, not a firewall rule.
Use `mp2.sh psql`, `mp2.sh workflows` and `mp2.sh objects`, which go through
`docker compose exec`.

A pre-existing `*:80` listener on this machine belongs to Docker Desktop
(`com.docker.backend`), not to MP2.

## Housekeeping

```bash
docker system df                    # image, container, volume and cache usage
docker builder prune -af            # reclaim build cache
infra/scripts/mp2.sh clean-derived  # reclaim derived object storage
```

Keep all container and corpus data on D:. C: is the small system volume and has already run
to near-zero once during this project, which corrupted a Docker layer.
